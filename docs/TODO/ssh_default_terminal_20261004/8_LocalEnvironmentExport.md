# 本地环境导出与磁盘释放

> 已放弃：维护者决定不提供本地环境的导出与删除入口。本文保留下来只作为记录，其中的导出形态、删除范围与二次确认要求可以在日后重新需要时直接复用。

## 背景

决策 D1 让本地 Ubuntu 只从默认路径移除、仍随包提供；原本的决策 D5 要求“导出后再删除”，即让用户把自己的本地环境搬走再释放磁盘，该决策现已撤销。下文保留当时的用户数据位置调研与流程设计，供日后需要时复用。用户数据实际落在：

- rootfs 家目录：`{filesDir}/usr/var/lib/proot-distro/installed-rootfs/ubuntu/home/...`（路径见 `app/.../util/PathMapper.kt:20-31`）
- 用户在 Ubuntu 内安装的包与编译产物同在该 rootfs 内
- 应用侧引用这些路径的还有 MCP 插件运行时目录（`MCPDeployer.kt:179-188`）

## 导出形态

- 打包为单个归档：对整个 rootfs 或仅家目录打包为 `tar.zst` 或 `tar.xz`，写入用户可见目录（如 `/sdcard/Download/operit-ubuntu-export-<日期>.tar.xz`），并在完成后展示路径与大小
- 同步到远端主机：当默认目标已配置且连通时，把家目录打包后经 SFTP 上传到远端指定目录，作为“把本地环境搬到远端”的一步
- 只导出用户数据：默认只打包家目录与 `/etc` 内的用户改动，避免把 apt 缓存与系统文件一起搬走

## 删除流程

- 删除动作必须显式触发，且需二次确认，文案写清“将删除本地 Ubuntu 环境与其中的文件”
- 删除范围：rootfs 目录（`installed-rootfs/ubuntu`）与 `{filesDir}/usr` 下的相关缓存；`liboperit_*` 原生件与资产保留，以便用户之后重新安装
- 删除前检查导出是否已完成；未导出时提供“先导出再删除”“直接删除”“取消”三条明确选项
- 删除后状态回到“未安装本地环境”，环境配置页重新可安装；目标若指向本地则要求用户切换到远端或其他目标

## 与目标模型的关系

- 导出与删除都在设置页的“本地环境”分区，与目标选择相邻，避免用户在不知情的情况下删除正在使用的环境
- MCP 插件若运行在本地方案下，删除前提示将失效的插件，并给出改部署到远端的选择

## 验证要点

- 导出归档可解压且与源目录内容一致（抽样校验文件数与哈希）
- 导出到远端时校验远端文件大小与本地归档一致
- 删除后磁盘占用下降，重装可回到可用状态
- 删除过程中断不留下半删除状态：要么完成删除，要么保持可恢复
