# 验证计划

## 单元测试

- 目标解析：已配置主机、未配置主机、显式切到本地、显式切到远端各自的选择结果
- 传输抽象：本地 PTY 与 SSH channel 两种实现的行为一致性（写入、读取、关闭、退出码、存活判断、resize 调用）
- 主机密钥：TOFU 状态机（新主机、指纹一致、指纹变化、known_hosts 解析与写回）
- 凭据迁移：旧明文配置读入、迁移到加密存储、旧键清除、损坏数据不静默丢弃
- 提示词生成：`environment` 取值与文案在两种语言下都与实现一致
- 路径解析：`remote` 目标不做 Android↔rootfs 映射，`local` 目标保持现有映射

## 集成测试

需要一个真实 sshd 作为夹具。tabssh 仓库自带 `deps/tests/sshd`（Dockerfile 与 entrypoint）可作参考，本地与 CI 均可起容器。

算法与认证矩阵：

- 密码认证
- 密钥认证（无口令 ed25519、带口令 ed25519）
- 服务端只提供 rsa-sha2-256/512
- 服务端按 OpenSSH 8.8+ 默认禁用 `ssh-rsa`（验证旧 JSch 会失败、新依赖可连）
- 首次连接出现 TOFU 提示，指纹变化必须失败

功能矩阵：

- exec 退出码：0、非 0、127，以及 stdout/stderr 区分
- 超时与中断：`timeoutMs` 生效、Ctrl-C 中断前台命令
- resize：改窗口大小后远端 `stty size` 与 `$LINES/$COLUMNS` 同步
- 长任务：`tmux` 会话 attach/detach，断线重连后仍在
- 大输出：持续高速输出不丢字、不卡 UI
- SFTP：读、写、列表、重命名、删除
- 端口转发：8751 → 8752 的 MCP 桥
- 反向隧道：远端回连手机侧 sshd，挂载存储与 SFTP 可用
- 心跳：空闲超过 `ServerAliveInterval` 不断线

## 端到端

- 首启引导：无主机配置时给出“添加主机”，不自动进入本地 Ubuntu
- 切换目标：显式确认、状态可见、切换后隐藏执行与文件操作都跟随
- 失败呈现：远端不可达时报错清晰，当前目标不被改写，本地目标仍可手动选择
- SSH-only 路径不产生 rootfs 解压，磁盘占用可核对
- 本地目标回归：安装包、进入 Ubuntu、apt 源切换、既有功能不退化
- Agent 视角：`environment=linux` 落到远端目标，`repo:` 语义不变
- MCP：按目标部署插件运行时，桥接与调用成功

## 性能基准

在同一台设备与同一台远端主机上固定工作负载，分别测本地 proot 与远端 SSH：

- 会话就绪时间（从点击到出现提示符）
- `npm install`（同一示例工程，使用国内镜像）
- 一段 CPU 密集的 Python 或编译任务
- `grep -r` 遍历同一份仓库
- 记录 `PerformanceMonitorManager` 的进程树与 CPU 采样，确认远程会话不再产生 proot 进程树

结果写入本目录的验证记录文档，并在结论中给出“何时仍然值得用本地环境”的判断。

## 门禁与文档

- JVM 单测与既有 CI 检查保持通过
- 本地化与文档链接检查通过
- 更新终端目标与 SSH 使用说明，并同步中英文

## 验收标准

- 未配置主机的新安装不会自动进入 proot Ubuntu
- 配置主机后，终端会话、隐藏执行、文件操作默认都在远端，且全程不经 proot
- 主机密钥默认校验，凭据不再明文落盘
- 老用户升级后本地目标仍可用且不被静默改变
